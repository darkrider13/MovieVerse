## 4. Conventions / hard-won rules (IMPORTANT)
1. dp == CSS px. **CSS border adds to the box size, Compose border does not**: every bordered component gets +1dp padding on each side (already done everywhere; keep doing it).
2. Text: default 15sp, line-height 1.45 (`MvText`, lineHeight is a multiplier). Dialog fonts are 13sp (`BtnSize.Dialog`, `FieldSize.Dialog`).
3. Click without ripple: `Modifier.plainClickable`.
4. Never use `IntrinsicSize` on layouts that contain BoxWithConstraints/SubcomposeLayout (runtime crash).
5. Movies are mutated only through `Enrich` functions (they run on `StateDispatcher`); UI reads them directly; call `AppData.render()` after changing movies/folders/statuses.
6. Dialogs: `MvDialog(onDismiss, padding, sideMargin, fillHeight, onClose)`. Web dialogs do not close on outside tap.
7. JS `Date.now()` = Long ms; absent field = undefined (use `m.has()`), null is different.
8. TV shows have NEGATIVE tmdb ids everywhere.
9. Port by reading the ORIGINAL js function by NAME (`grep -n "function name" www/index.html`), never from memory. Line numbers in notes are unreliable (base64 images inflate lines).
10. (10A) `AppData.uname` is now Compose state (hero title updates while typing in Settings). `MvTextField(fixedHeight=)` (key boxes are exactly 40dp), `MvButton(borderColor=)` (blinking red border), `BtnSize.SettingsSmall` (#sdlg .srow.ex .btn: 12sp, 6/10).
11. (10A) **Toasts inside dialogs:** a `MvDialog` is its own window and would hide / dim the main toast. So `ToastState.dialogs` counts open dialogs; the main `ToastHost` hides while one is open and the TOP dialog draws the toast itself (`ToastHost(inDialog = true)` at the end of MvDialog). Nothing else to do: just call `toast.show(..)` / `ToastBridge.show(..)`.
12. CSS margin collapsing was checked by hand in Settings (h2 mb 4 + label mt 12 = 12, label mb 4 + .srow.ex mt 6 = 6, .atabs mt 6 comes after the label's own mb 4). Do the same for the next dialogs.
13. (10D) The list `AppData.movies` is only ever structurally changed on the MAIN thread (screens read it there); movie contents are changed on `StateDispatcher`; `putMany` is called from `StateDispatcher`. A flow that adds many movies: clean them on StateDispatcher, `withContext(Dispatchers.Main){ movies.addAll }`, then `putMany`. Progress dialogs of long flows live in their own composable (`ImportDialogs`) so caption updates do not redraw HomeScreen.
15. (Step 11) Backup file = xlsx (export) and xlsx or json (import). Any new field in a movie needs NO change in the xlsx code (every field gets its own column automatically). If a new value type ever appears, extend `XlsxCodec` (both directions) so the round trip stays exact. `Backup.write` (json) must stay: the safety copy uses it.
14. How exact sizes were found: the original app was rendered in headless Chromium (Playwright, mock TMDB via request routing), screenshots + `getBoundingClientRect` + computed styles were read. If Playwright is available do the same for the remaining dialogs.

### Step 11 : Excel (.xlsx) backup (extra feature, DONE) - Export AND Import
User asked: Settings Export/Import must work with Excel files; old .json backups must still import. **No library is used** (no Apache POI): an .xlsx is a zip of XML files, written with `ZipOutputStream` and read with `ZipFile` + `XmlPullParser` (nothing new in `build.gradle.kts`).
Files: `data/XlsxCodec.kt`, `data/XlsxBackup.kt`, `data/XlsxReader.kt`; changed `data/Backup.kt` (file name now `movieverse-backup-YYYY-MM-DD_HH-mm-ss.xlsx`), `ui/settings/ExportFlow.kt` (writer + MIME type), `ui/settings/ImportFlow.kt` (json / xlsx branch).
**Export** (Save File / Share / progress dialog / success dialogs unchanged, only the file is .xlsx, MIME `XlsxCodec.MIME`). Sheets: `Movies`, `Folders`, `Statuses`, `Settings`.
- Movies: row 1 = header (bold, frozen). Columns A-E: `Title`, `Year`, `Status` (= the real fields title/year/status), `My Rating` (= `LibraryLogic.scoreOf(m)`: `score`, else `rating*2`; empty when 0), `IMDb Rating` (= `Enrich.imdbRating(m)` only: IMDb value from MDBList / XMDb / OMDb, never another source; number cell when numeric). After them every other field of the movies is its own column named exactly like the field (`id` first, then in order of first appearance); `md`, `ott`, `genres`, cast etc. = JSON text in one cell. Rows are written one movie at a time (progress caption every 500 movies), the zip is streamed, so 10000+ movies never sit in memory as one text. Fields are read with `names()`/`opt()` with a retry on `ConcurrentModificationException` (the app may still change a movie while exporting).
- Folders / Statuses: one column per field (`id,name,status,color` / `id,name`, plus any extra field). Settings: header `Setting | Value | API name | Custom | Key 1..N`; row `name`, row `theme`, one row `api` per API (B = id, C = name, D = 1 if custom, E.. = keys).
**Cell rules (XlsxCodec, same code for export and import, this is what makes the round trip 100%):** string = text cell (a string that is empty / `null` / starts with `{` `[` or the invisible U+200B gets ONE U+200B in front, removed again on import); number = number cell (whole numbers come back as Long, others as Double); boolean = TRUE/FALSE cell; JSON null = the text `null`; object/array = JSON text; missing field (JS undefined) = no cell. Text longer than 30000 chars (Excel cell limit 32767) continues in extra columns `<field>~2`, `<field>~3`... (joined on import). Characters XML cannot hold (control chars, CR, lone surrogates) are written `_xHHHH_` like Excel does, and a literal `_xHHHH_` is written `_x005F_xHHHH_`.
**Import:** `importFile` looks at the first 4 bytes ("PK" 3 4 = zip = xlsx, otherwise the old json path), NOT at the file name. xlsx path: the picked file is copied to the cache folder (needs random access; deleted afterwards), `XlsxReader` reads the Movies sheet row by row with a pull parser (shared strings of an Excel-saved file are kept in a temp file with an LRU cache, not in memory), 200 rows per piece go through the SAME `flush` (normM, skip same id, add + putMany) and `finish` as the json path (same merge rules, nothing removed, same progress dialog "NN%  ·  X movies", same result dialog / toasts). Then Folders, Statuses, Settings are turned into the same JSON text the json path produces (`r.extra`), so `finish` is unchanged (`finish(r, found, p)` now takes a Boolean instead of the BackupScan). A zip without a Movies sheet / a broken zip -> toast "That is not a valid MovieVerse backup.".
**Editing in Excel:** `My Rating` is for reading AND editing: on import, if the number in that cell differs from the movie's own score (`LibraryLogic.scoreOf` of the other columns) the field `score` is set to it (empty cell with an old score -> `score` 0); if it is the same, nothing is touched (so a movie that only has `rating` does not gain a `score`). `IMDb Rating` is NOT imported (real data comes back from the real fields). The other columns are the real fields, so changing `score`, `rating`, `status` etc. there works too.
Kept on purpose: the safety copy before an import is still the json `Documents/MovieVerse/before-last-import.json` (fast, lossless, same as before).
Known simplifications: dates typed in Excel into a text field are stored by Excel as numbers and come back as a number; `IMDb Rating` text that is not a number is written as text; no Excel autofilter.
Not compiled / not run (same as everything else). The XML templates (content types, rels, workbook, styles, sheet layout, inline strings, `_x000D_` escapes, frozen pane) were checked by building the same XML in Python and opening it with openpyxl and LibreOffice (both open it and show the right cells). The Kotlin code itself still needs the first GitHub build.
